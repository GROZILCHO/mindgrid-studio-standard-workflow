# Phase 12: Retrospective

Status: Draft

## Purpose

Capture what was learned after a project or major phase so MindGrid Studio Standard Workflow can improve over time.

## When To Use This Phase

Use this phase after launch, after a major phase, or after a project pause where reusable lessons were discovered.

## Main Questions

- What worked?
- What caused friction?
- Which decisions became standards?
- What issues should be prevented next time?
- What reusable assets/templates were created?
- What workflow improvements should be made?
- Should CHANGELOG.md be updated?

## Required Inputs

- CURRENT_STATUS.md.
- ISSUES_LOG.md.
- DECISIONS_LOG.md.
- NEXT_ACTIONS.md.
- PROJECT_HANDOFF.md if available.
- Launch/QA/deployment notes.

## Expected Outputs

- PROJECT_RETROSPECTIVE.md completed.
- Workflow improvement actions.
- Recommended template/checklist/prompt changes.
- CHANGELOG.md recommendation if workflow changes are needed.
- DECISIONS_LOG.md entries where real workflow decisions are made.

## Recommended Steps

1. Summarize project and final state.
2. Record what worked.
3. Record what caused friction.
4. Identify decisions that became standards.
5. Identify issues to prevent next time.
6. List reusable assets/templates created.
7. Define workflow improvement actions.
8. Recommend CHANGELOG.md updates if the workflow should change.

## Codex / Agent Involvement

- ChatGPT Lead Assistant can facilitate retrospective.
- Codex may update retrospective docs only when explicitly scoped.
- Rosen / MindGrid Studio decides which lessons become standards.

## Tracking Docs Update Rules

- Update PROJECT_RETROSPECTIVE.md for the retrospective.
- Update NEXT_ACTIONS.md with workflow improvement tasks.
- Update ISSUES_LOG.md only for unresolved project risks.
- Update DECISIONS_LOG.md only for real workflow decisions.
- Recommend CHANGELOG.md updates when master workflow changes are needed.

## Completion Criteria

- PROJECT_RETROSPECTIVE.md captures usable lessons.
- Improvement tasks are listed.
- Standards and prevention rules are identified.
- Future workflow changes are clear.

## Stop Conditions

- Project status is unclear.
- Issues or decisions were not reviewed.
- Retrospective would become unsupported opinion.
- Workflow changes are proposed without owner approval.

## Handoff Notes

New sessions should inspect PROJECT_RETROSPECTIVE.md, DECISIONS_LOG.md, NEXT_ACTIONS.md, and CHANGELOG.md if workflow changes are planned.
