# Phase 02: Project Intake

Status: Draft

## Purpose

Capture business context, target audience, project goals, project type, language scope, available content/assets, constraints, and risks before strategy or implementation.

## When To Use This Phase

Use this phase immediately after project setup and before proposing design, routes, content, or code.

## Main Questions

- What does the business do?
- Who is the target audience?
- What is the primary project goal?
- What is the primary conversion goal?
- What project type is this?
- What languages are required?
- What competitors/reference sites matter?
- What content/assets already exist?
- What constraints and risks are known?

## Required Inputs

- Business context from Rosen / MindGrid Studio.
- Known audience and offer details.
- Existing website or brand materials if available.
- Known platform preference if any.
- Known deadline, access, and content constraints.

## Expected Outputs

- PROJECT_BRIEF.md completed enough for strategy.
- PROJECT_RULES.md started.
- CURRENT_STATUS.md updated.
- NEXT_ACTIONS.md updated with strategy tasks.
- ISSUES_LOG.md updated for missing access/context.

## Recommended Steps

1. Ask structured intake questions.
2. Record business context.
3. Define target audience and decision-makers.
4. Define primary and secondary goals.
5. Identify project type and platform uncertainty.
6. Record language scope.
7. Record existing content/assets.
8. Record constraints, risks, and unknowns.
9. Fill PROJECT_BRIEF.md.
10. Identify next strategy task.

## Codex / Agent Involvement

- ChatGPT Lead Assistant leads intake.
- Codex should not implement during this phase unless asked to organize documentation.
- Specialist agents may be used only after intake context exists.

## Tracking Docs Update Rules

- Update CURRENT_STATUS.md after intake summary is ready.
- Update NEXT_ACTIONS.md with strategy and missing-input tasks.
- Update ISSUES_LOG.md for missing access, content, or unclear ownership.
- Update DECISIONS_LOG.md only if a real scope/platform decision is made.

## Completion Criteria

- PROJECT_BRIEF.md has usable project context.
- Primary goal and conversion goal are known.
- Project type is identified or explicitly marked unknown.
- Key risks are recorded.

## Stop Conditions

- Business goal is unclear.
- Project owner is unclear.
- Audience is unclear.
- Project type is unclear and blocks planning.
- Required access/content context is missing.

## Handoff Notes

New sessions should inspect PROJECT_BRIEF.md, PROJECT_RULES.md, CURRENT_STATUS.md, NEXT_ACTIONS.md, and ISSUES_LOG.md.
