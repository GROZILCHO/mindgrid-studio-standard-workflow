# PMO v2 Project Template

Reusable project management and handoff template for complex MindGrid Studio projects managed across ChatGPT, Codex, QA, client communication, and commercial planning.

## When To Use

Use this template when:

- starting a new complex project;
- restarting a paused project;
- handing a project to a new PM / PMO assistant;
- separating client-facing work from internal product work;
- preparing a commercial offer from an active technical demo.

## How To Start A New PM Chat

1. Copy this folder into the project documentation area or reference it from the project repository.
2. Fill in `01_PROJECT_HANDOFF.md` and `02_PROJECT_STATUS.md`.
3. Paste `00_PM_SYSTEM_PROMPT.md` as the PM assistant operating prompt.
4. Ask the PM assistant to read the filled files in the recommended order.
5. Continue by issuing concrete specialist tasks to Codex, QA, design, content, translation, or commercial support.

## Recommended Read Order

1. `00_PM_SYSTEM_PROMPT.md`
2. `01_PROJECT_HANDOFF.md`
3. `02_PROJECT_STATUS.md`
4. `03_WORKSTREAMS.md`
5. `09_NEXT_ACTIONS.md`

## Files

- `00_PM_SYSTEM_PROMPT.md` - reusable PMO assistant system prompt.
- `01_PROJECT_HANDOFF.md` - full handoff template.
- `02_PROJECT_STATUS.md` - current status snapshot.
- `03_WORKSTREAMS.md` - parallel workstream tracker.
- `04_REPOSITORIES.md` - repository registry.
- `05_TECHNICAL_STATE.md` - technical state template.
- `06_CLIENT_STATUS.md` - client communication status.
- `07_COMMERCIAL_PREPARATION.md` - offer preparation template.
- `08_TRANSLATION_PROJECT.md` - localization workflow template.
- `09_NEXT_ACTIONS.md` - action tracker.
- `10_DECISIONS_LOG.md` - decision history.

## Maintenance

- Update status snapshots after each milestone.
- Keep decisions separate from assumptions.
- Do not store secrets, credentials, tokens, or private access details.
- Mark demo, staging, release candidate, stable, and production states explicitly.
- Keep commercial assumptions and final approved pricing separate.
