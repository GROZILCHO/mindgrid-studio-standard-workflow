# Issues Log Template

## Purpose

Reusable project tracking document for bugs, blockers, risks, and unresolved questions that should not depend on chat memory.

Status: Draft

## Usage Rules

- Update when bugs, blockers, risks, or unresolved questions are found.
- Keep issue entries specific and actionable.
- Do not use this file for completed task summaries.
- Do not duplicate normal next steps here unless they represent a risk, blocker, bug, or unresolved question.
- Move resolved work forward by updating status and resolution notes.

## Severity Values

- Critical: blocks launch, deployment, data safety, legal accuracy, payment, or core user flow.
- High: significantly affects quality, conversion, SEO, accessibility, or implementation progress.
- Medium: should be fixed but does not block immediate progress.
- Low: minor cleanup, polish, or future improvement.

## Status Values

- Open
- Investigating
- Blocked
- Resolved
- Deferred
- Won't Fix

## Template Structure

| ID | Severity | Affected Area | Description | Status | Owner | Proposed Action | Resolution Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ISSUE-001 | Low/Medium/High/Critical | Placeholder area | Placeholder issue or risk | Open | Rosen / ChatGPT / Codex | Placeholder next action | Placeholder resolution notes |

## Placeholder Content

- Add one row per issue, blocker, risk, or unresolved question.
- Keep descriptions factual and short.
- Link related next actions, decisions, files, tasks, or validation output when useful.

## Maintenance Notes

- Codex should update this file when a task uncovers a bug, blocker, risk, or unresolved question.
- ChatGPT Lead Assistant may use this file to plan QA, recovery, or follow-up tasks.
- Rosen may use this file to decide whether an issue blocks launch or can be deferred.
