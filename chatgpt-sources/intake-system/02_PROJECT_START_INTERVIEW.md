# Project Start Interview

Status: Source Pack

## Purpose

Use this interview to gather the minimum information needed to classify a project, choose a starter kit, establish baseline docs, and recommend the first controlled action.

Ask questions in phases. Do not propose code or design before the core context is usable.

## 1. Project Identity

- What is the project name?
- Who is the client, brand, or internal owner?
- Who makes final decisions?
- Is this a new project, redesign, migration, or improvement sprint?
- What is the primary project goal?
- What is the target launch date or timeframe?
- What language or languages are required?

## 2. Business And Audience

- What does the business offer?
- Who is the primary audience?
- Who makes the buying or contact decision?
- What user problem should the website solve?
- What is the primary conversion goal?
- What proof points, differentiators, or approved claims exist?
- Which claims must not be assumed?
- Are there reference or competitor sites?

## 3. Platform And Technical Context

- Is the platform general/not decided, React/Vite, Next.js, WordPress, WooCommerce, static HTML, or other?
- Does a repository already exist?
- Does a local project folder already exist?
- Is there existing code or an existing live site?
- What hosting and deployment method are expected?
- Is local preview available or required?
- For WordPress: are admin, hosting, database, staging, backup, theme, builder, and plugin details known?
- For React/Vite or Next.js: are routes, build commands, output behavior, and deployment target known?

## 4. Content, SEO And Assets

- What pages are likely required?
- What content already exists?
- What content is missing?
- Are there legal, cookie consent, analytics, or tracking requirements?
- What SEO-critical pages, languages, or legacy URLs exist?
- Are sitemap, robots, canonicals, metadata, redirects, or structured data relevant?
- What visual assets already exist?
- Are new images needed?
- Are image naming, alt text, optimization, and usage rules required?

## 5. Starter Kit Decision

- Is the platform undecided or is the work primarily planning/documentation?
- Is the project a file-based React/Vite static or prerendered website?
- Is the project WordPress, WooCommerce, Elementor, Gutenberg, custom theme, or child theme work?
- Does an existing repository already contain files that must be preserved?
- Which starter-kit docs should be copied or adapted?

## 6. First Operational Plan

- Confirm repository, local folder, branch, and clean Git state.
- Confirm `AGENTS.md` and `docs/` exist.
- Confirm the minimum planning docs exist or need to be filled.
- List missing critical information.
- Recommend the first documentation task.
- Prepare the first read-only Codex bootstrap audit.
- Prepare the first narrow implementation task only after the audit.
- Identify how the first browser-visible baseline will be verified.
- Define the next human approval point.

## Required Final Intake Output

Return:

1. Project classification.
2. Recommended starter kit.
3. Missing critical information.
4. Required first documents.
5. Recommended repository/folder setup.
6. First Codex bootstrap/audit recommendation.
7. Stop conditions.
8. Next human action.
